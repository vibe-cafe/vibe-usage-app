# Vibe Usage Test 外测说明

这是未公证的临时外测包，与正式版 Vibe Usage 分开安装和保存界面偏好。
它不会读取其他 macOS 用户的数据，也不会把订阅配额或诊断日志上传到 Vibe Usage。

## 运行条件

- macOS 14 或更新版本。
- 已安装 Node.js 20 或更新版本，并且 `npx` 可用。
- 需要测试的 Codex、Claude Code、Kimi Code、Grok、Cursor 或 OpenCode Go 已由测试者本人安装、登录和使用。

## 首次打开

1. 解压 `VibeUsage-Test.zip`。
2. 按住 Control 点击 `Vibe Usage Test.app`，选择“打开”。
3. 再次点击系统提示中的“打开”。
4. 如果仍被拦截，请到“系统设置 → 隐私与安全性”，点击对应的“仍要打开”。

请勿覆盖或删除正式版 `Vibe Usage.app`。外测包名为 `Vibe Usage Test.app`。
订阅配额无需登录 Vibe Usage。要同步 Token 和查看用量，点击「登录并链接数据」，在浏览器核对验证码并确认。默认站点为 vibefriends.com，已配置自定义服务器时使用该服务器。
链接后，读取用量或切换终端、工具、项目筛选时，App 会按系统代理设置，用 Vibe Usage 的 Key 向同一服务器查询所选周期的去重活跃时长和 AI 工时。重置配置解绑后停止查询。

## 配额测试

- 面板顶部的「订阅配额」是一排产品图标 Tab：已生效的排前面且是彩色，未生效的置灰排在后面，可拖动排序；最右侧是一个齿轮图标，点开设置页（勾选/取消产品、看每个产品的检测状态）。下方是已生效产品的卡片，一行两张、可以横向滑动：点 Tab 会滑到对应产品，反过来滑动卡片时高亮的 Tab 也会跟着走。已生效但取不到数据的产品，Tab 上会多一个琥珀色小点，点它滑到卡片看具体原因；置灰的产品不展示卡片，点它直接进设置页。全部产品都关掉时，这一段只剩那排图标。
- Codex、Claude Code、Kimi Code 使用测试者本人的官方客户端登录状态。
- Grok 由同步工具运行测试者本人已安装、已登录的官方 `grok` 命令行，只查一次当前账期（不开对话、不发提示词、不耗额度）；查不到时读官方 CLI 日志里已经写入的结构化配额记录。显示「需要登录」时，请先在终端运行 `grok login`。
- Cursor 目前只识别安装状态，等待官方稳定配额接口，不读取 Token、Cookie 或数据库。
- ZCode 只有在测试者主动输入 BigModel 或 Z.ai Coding Plan API Key 后才读取配额；Key 仅保存在外测包独立的本机钥匙串项中。
- OpenCode Go 读取 OpenCode 在本机保存的登录（API Key 或 OpenCode 账号登录；只读、不落盘、不写日志、不续期），显示 5 小时 / 每周 / 每月三个窗口；未订阅 Go 的账号显示「未订阅 OpenCode Go」，如刚订阅请在面板里点一次「重试」。

## 反馈问题

在设置页选择“导出诊断日志…”，把导出的 JSONL 文件发给测试组织者即可。
日志只包含时间、Provider、状态、错误码、计量项数量、应用版本与系统版本，不包含路径、账号、Token、Cookie、API Key、响应正文或聊天内容。

不要发送任何产品的凭据文件、浏览器 Cookie、登录二维码、密码或完整终端日志。
